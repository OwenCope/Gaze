# Accessibility Audit — Settings, Enrollment, Lock Screen panel

Scope: `Sources/App/`, `Sources/Enrollment/`, `Sources/LockScreen/`. `Sources/Setup/` deliberately excluded. Source-only review; no build, no screen reader run. Severity: HIGH blocks a task, MEDIUM makes it harder or ambiguous, LOW is polish.

## Verdict

Every switch row in Settings is nameless to VoiceOver. `SettingToggle` renders `Toggle(title, isOn:)` with `.labelsHidden()` and only an `.accessibilityHint`, never an `.accessibilityLabel`, so the title a sighted user reads is hidden from the accessibility tree and nothing replaces it — a VoiceOver user hears an anonymous switch (plus a detail string, if any) for "Unlock my Mac", "Show captions", and every other toggle in the window. One missing modifier, app-wide effect.

## High

- `Sources/App/Theme.swift:771` — `Toggle(title, isOn: $isOn)` followed by `.labelsHidden()` (`:772`) and only `.accessibilityHint(detail ?? "")` (`:773`), with no `.accessibilityLabel` anywhere on the toggle. A VoiceOver user hears an unlabeled switch and cannot tell which setting they are toggling; every `SettingToggle` in Settings (unlock, walk-away lock, captions, autofill rows) is affected. Direction: add `.accessibilityLabel(title)`.
- `Sources/App/SettingsView.swift:1002` — `Toggle("Lock when I walk away", isOn: walkAwayBinding)` with `.labelsHidden()` (`:1003`) and only `.accessibilityHint("Checks for absence after 20 seconds without input")` (`:1004`). Same defect outside the shared component: VoiceOver announces the hint but never the name "Lock when I walk away", so the user cannot identify the control. Direction: add `.accessibilityLabel("Lock when I walk away")` (or route through `SettingToggle` once it is fixed).
- `Sources/App/AutofillSettings.swift:242` — `Image(systemName: "minus.circle.fill")` as the entire label of the per-app Remove `Button` (`:234`), with only `.help("Remove \(savedApp.name)")` (`:246`) and no `.accessibilityLabel`. A VoiceOver user hears a generic button/image and cannot tell it removes the saved app, unlike the FaceCard remove button which is labeled. Direction: add `.accessibilityLabel("Remove \(savedApp.name)")`.

## Medium

- `Sources/LockScreen/NotchCapsule.swift:691` — `private var lockChip: some View { Image(systemName: model.phase == .unlocked ? "lock.open.fill" : "lock.fill")` (`:692`) carries no `.accessibilityHidden(true)` and no label, while `GazeFaceMark` separately announces "Locked"/"Unlocked". If the panel is reachable to VoiceOver, the user hears a redundant "lock, image" next to the mark's own status label. Direction: hide the chip and let the mark speak.
- `Sources/Enrollment/EnrollmentRing.swift:56` — `.fill(isFilled ? filled : isTarget ? Color.primary : empty)`. Ring progress (how many of N ticks are covered, which segment is the target) exists only as tick colour/length; the file contains no `accessibilityLabel`, `accessibilityValue`, or announcement (only the `reduceMotion` environment read at `:17`). A VoiceOver user gets no "3 of 8 segments" equivalent. (Its current use sites are in `Sources/Setup/`, out of scope, but the component itself offers nothing to any host.) Direction: expose covered-count/target as an accessibility value on the ring.
- `Sources/App/Theme.swift:1021` — `InfoButton` popover (`:1056`–`:1081`): opening moves no focus into the popover, there is no Escape-to-dismiss or focus restore, and the `opensOnHover` path (`Theme.swift:589`, section headers) opens only on pointer hover, so a keyboard user who tabs to the ⓘ must discover that activating pins it. A keyboard/VoiceOver user may never hear the explanation the popover holds. Direction: move focus into the popover on open and return it on dismiss.
- `Sources/LockScreen/NotchCapsule.swift:513` — `.opacity(reduceMotion && !model.isExpanded ? 0 : 1)`. Under Reduce Motion `expanded` is forced true (`:276`), so whenever the model is not expanded the whole capsule — including the resting padlock — renders fully transparent. A person with Reduce Motion on may lose the lock indicator entirely. Direction: confirm whether the window is ever shown in that state; if so, gate only the animation, not the opacity.
- `Sources/LockScreen/NotchCapsule.swift:527` — caption `Text(prompt)` at 11pt semibold in `.white` (`:533`–`:539`) drawn over translucent glass over the user's wallpaper, with only a +0.22 `lightWallpaperBoost` (`:676`) defending contrast on light desktops. A low-vision user on a bright wallpaper may be unable to read movement guidance or rejection reasons. No ratio is claimed from source. Direction: measure caption contrast on-screen over light wallpapers in both glass styles.
- `Sources/Enrollment/RecognitionTestPanel.swift:50` and surrounding — live `readout.status`/`score` text (throttled to ~10Hz in `RecognitionTestView.swift`) has no announcement or live-region equivalent; the combined elements read correctly on demand but a VoiceOver user practising a movement is never told when state flips to "Recognised" or "Movement complete" without manually re-reading. Direction: announce status transitions only (not the 10Hz score).
- Fixed-width containers that clip scaled text at larger Dynamic Type sizes: `Sources/App/SettingsView.swift:1883` (`.frame(width: 84)` on the face-name field), `Sources/App/NotchSettings.swift:234` (`.frame(width: 48, alignment: .trailing)` on the slider value, e.g. "+40 pt"), `Sources/App/NotchSettings.swift:26` and `:54` (`.frame(width: 330)` on the segmented pickers), `Sources/App/AutofillSettings.swift:464` (`.frame(width: 460)` on the password sheet). The type itself scales (good) but the boxes do not, so a large-text user gets truncated names, values, or picker segments. Direction: replace fixed widths with min-widths or flexible layout and re-check at AX5.

## Low

- `Sources/LockScreen/NotchCapsule.swift:521` — `model.phase.isReturningToRest && !reduceMotion` hides the return-to-rest caption while the phase (and therefore `GazeFaceMark`'s label, `GazeFaceMark.swift:116`) still carries the movement prompt. A VoiceOver user hears an instruction ("Turn left…") the sighted user no longer sees. Direction: report the resting state in the mark's label during return-to-rest.
- `Sources/Enrollment/RecognitionTestView.swift:173` — `Image(systemName: "person.crop.rectangle")` and `:188` `Image(systemName: "video.slash")` have no `.accessibilityHidden(true)`, so VoiceOver spells out symbol names inside what is otherwise a status message. Direction: hide both decorative icons.
- `Sources/App/AutofillSettings.swift:400` — `.foregroundStyle(.blue)` on the sheet's checkmark submit button: a hardcoded hue on glass whose contrast is unmeasured, and which ignores the app's own rule that green/blue carry meaning. Direction: use the theme accent and measure on screen.
- `Sources/Enrollment/EnrollmentRing.swift:34` — `Theme.tickEmpty` is a fixed `Color(white: 0.34)` (`Sources/App/Theme.swift`), i.e. unfilled ticks never adapt to appearance or Increase Contrast; on a light ground the unfilled/filled distinction thins. Direction: resolve the empty-tick colour against appearance and test with Increase Contrast.
- `Sources/App/Theme.swift:1067` — InfoButton hover dwell (`.task(id: buttonHovered || popoverHovered)`, 350/250ms sleeps) is not gated on Reduce Motion; trivial, but it is pointer-only timing with no keyboard equivalent. Direction: leave as-is or open immediately on focus.

## Checked and clean

- FaceCard hover-revealed actions (`SettingsView.swift:1833`–`:1909`): camera badge and remove button both carry `accessibilityLabel`s, join the reveal condition via `@FocusState` (`portraitFocused`, `removeFocused` in `controlsVisible`), and are duplicated as named `accessibilityAction`s plus a `contextMenu` — the right-click path has a keyboard equivalent. No tap-only affordance.
- `SettingsNavigationRow.swift:15`–`:28`: a real `Button` with labeled row and hint; chevron hidden (`:20`). Keyboard activation and focus treatment come free.
- `SettingsChoiceMenu` (`Theme.swift:979`–`:980`), notch `Picker`s (`NotchSettings.swift:18`–`:27`, `:46`–`:55`), and `NotchAdjustmentRow` sliders (`NotchSettings.swift:226`–`:230`): `labelsHidden` paired with explicit label + value throughout.
- `StatusLine` (`Theme.swift:840`–`:841`): children combined with severity spoken ("Warning: …", "Problem: …") — colour is not the only channel.
- `ThemePreviewPicker.swift:32`: each theme button labeled with `accessibilityLabel(theme.title)` + `.isSelected` trait; thumbnails hidden (`:55`).
- Credit/account link glyphs (`SettingsView.swift:1348`–`:1373`): icon-only buttons, but each has `.accessibilityLabel("Open \(name)")` plus `.help`.
- Autofill sheet (`AutofillSettings.swift:358`–`:429`): Cancel/Save icon buttons labeled, username/password fields labeled with hints, `FocusState` order matches visual order, `.keyboardShortcut(.cancelAction/.defaultAction)` present.
- Caption-off safety: with `showNotchCaptions` off the caption is `accessibilityHidden` (`NotchCapsule.swift:542`), but `GazeFaceMark.accessibilityLabel` (`GazeFaceMark.swift:116`–`:130`) still announces every phase including the full challenge prompt with its "· 1 of 2" progress suffix — turning captions off removes sighted text, not the screen-reader equivalent.
- `GazeFaceMark.swift:111`–`:113`: mark is a single element (`children: .ignore`) with a per-phase label; caption symbols hidden (`NotchCapsule.swift:532`).
- `GazeSettingsPicker.swift:33`–`:61`: toolbar gaze-follow animation disabled under Reduce Motion; segments are a real `NSSegmentedControl` with tooltips and an accessibility label.
- `GazeCompanionView` (`Sources/Companion/GazeCompanionView.swift`): `accessibilityHidden(true)` with `canAnimate` gated on Reduce Motion — the demonstrating face never double-announces and never forces motion. (File outside scope, verified only for these two properties.)
- Focus order: no explicit ordering anywhere in scope, which is correct — order falls out of view order and matches the visual layout; the only `@FocusState`s (FaceCard, autofill sheet) extend, not reorder.
- `NotchAppearancePreview` (`NotchSettings.swift:177`–`:179`): `allowsHitTesting(false)` plus label + value summary; decorative wallpaper canvas underneath contributes nothing.

## Needs on-screen testing

- Whether the lock-screen panel window (`UnfocusableWindow`, `NotchCapsuleController.swift:41`) ever enters VoiceOver's tree; if it does not, the lockChip/GazeFaceMark findings are moot and lock-state feedback for blind users is the gap instead.
- Actual VoiceOver utterances for the labeled icon buttons (FaceCard, credit links, autofill Cancel/Save) and the combined recognition-test rows.
- Contrast ratios: notch caption over glass over light wallpaper; `.blue` checkmark on glass; `tickEmpty` ticks; tertiary text over the settings glass.
- Full keyboard pass: Tab reachability of every Settings row, DisclosureGroups, segmented pickers, sliders, and the Theme grid; popover open/focus/dismiss with keyboard only.
- Behaviour at AX1–AX5 text sizes for the fixed-width containers listed above.
- Whether status flips in the recognition test need announcements in practice, and whether the InfoButton hover delay causes focus loss for switch-control users.
