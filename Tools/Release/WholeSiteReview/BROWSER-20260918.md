# Secondary-page browser review, September 18

Reviewed the live website and the existing September 17 local preview in Aside.
No files in `gaze-site` were edited, and nothing was deployed. This report records
observations and the next implementation decisions, not a completed redesign.

The main findings are a gap between the live site and local work, a confirmed
keyboard defect in the live release gallery, and excessive introductory space in
the local secondary-page layouts.

## Confirmed problems

### 1. Several intended pages are absent from the live deployment

The three routes above return HTTP 404, while the saved local preview renders
them. Live Credits and navigation also differ materially from the local preview.
This explains why local improvements may not be visible on `gazeunlock.com`.

Before a deployment, establish the intended canonical source revision and check
these routes in its preview. The older live presentation is not a reason to
reimplement changes already present locally. This review does not establish that
the current canonical checkout is ready to deploy.

### 2. The live release lightbox leaves keyboard focus behind it

On `/releases/v0.0`, clicking the first "Open picture" button opened a dialog
named "Picture". `document.activeElement` remained the thumbnail button, and
`closest('[role="dialog"]')` returned false. Pressing Tab moved focus to the next
thumbnail behind the still-open dialog. Closing the dialog succeeded.

This reproduces the source concern recorded as F2 in the earlier site review.
The counterpart is `src/components/release-gallery.tsx`. The next source pass
should focus the dialog's Close button, contain Tab navigation, support Escape,
and restore focus to the originating thumbnail. Give each thumbnail an image
description instead of making every accessible name "Open picture". Keep the
existing release data, image order, and authorization rules.

Acceptance: keyboard open, Tab and Shift-Tab containment, Escape, focus return,
and picture-position announcements, with one and multiple images.

### 3. The shared local introduction delays the page's useful content

Measured on local Features:

- Introduction height: 390.7 CSS px.
- Top/bottom padding: 80/64 px.
- H1 size: 64 px.
- Product-tour top: 454.7 px in a 900 px-high viewport.
- No horizontal overflow at this desktop size.

The counterpart is `src/components/page-intro.tsx`. The H1, eyebrow, paragraph,
and jump links consume roughly half the first screen before the product media.
This matches the owner's spacing feedback. The shared component affects Features,
How It Works, Security, and Releases, so fix this once rather than adding per-page
negative margins.

Use a 32–48 px title scale, 40–48 px top padding, and 32–40 px bottom padding as
the starting values. Remove the duplicated visible eyebrow. Keep descriptions to
one useful sentence and reduce the gap before optional jump links. Re-measure
the result at desktop and mobile widths; these values are recommendations, not
already-verified changes.
